# Landscape subagents 1.0.2

`org.jresearch.ai/landscape-subagents@1.0.2` is a passive, frozen VibeVM
`flow`. This PATCH removes private producer provenance from the distributable
materials while retaining the delegation policy, child-profile matrix, MIT
license and consumer contract. Earlier source versions remain unchanged in
producer history. Publication, remote tags and consumer adoption are separate
events, not consequences of `frozen = true`. `publish = false` remains unchanged.

## Version contract

This version contains the complete accepted delegation policy, including its
child-profile matrix, with the transport adaptations listed below. It covers
useful proactive delegation at all supported parent efforts, independent parallel
assignments, reassessment, zero-helper cases, bounded context, per-child model
and effort, follow-up reuse, coordination, integrated verification and consumer
authority. There is no mandatory helper count or guaranteed runtime effect.

Installing the flow only makes guidance available. A consumer decides whether
to adopt it in applicable instructions, which models and efforts are allowed,
what delegation the task permits, and when a future package update is accepted.
The [conditional boot](vibevm/vibespecs/boot/landscape-subagents.md) routes to the
full [policy](vibevm/vibespecs/protocols/subagents.md) only for an explicitly
adopted flow and relevant permitted work. Setup detail is loaded only when
assessing adoption or an update. A native static INDEX entry does not make the
policy unconditional.

The package configures no agents, roles, models, tools, client settings or
external actions. Runtime restrictions override suggestions. Subagents On does
not load external instructions, and this flow cannot replace a developer-mode
message or reproduce Ultra's configuration. No model access, CLI minimum,
subscription saving or scheduling improvement is promised. The dated child
matrix is a recommendation, not a provider entitlement or consumer allowlist.

Use the installed version throughout a task. There is no fetch of moving
Landscape `main`, dynamic routing service, quota router, resolver or dependency
on the sibling model-guidance flow. Admitted parent/child profiles and consumer
review, release and credential boundaries remain in force. Relay executes only
consumer-resolved profiles. Adoption and runtime checks are described in the
[adoption guide](vibevm/vibespecs/guides/adoption.md).

## Canonical source and projection

The producer's canonical policy remains the source authority; this package is a
versioned projection. Exact accepted-source identities, private source links and
source-equivalence machinery remain producer-only. Policy and
[runtime evidence](vibevm/vibespecs/guides/runtime-evidence.md) retain their
**October 9, 2026** review dates. They are not refreshed claims about every
current client. The runtime note cites the inspected public provider source.

The policy transport adaptations are:

1. Replace the source-relative model-evidence sentence with a producer-evidence
   description. The complete delegation recommendations remain self-contained;
   the producer's private evidence is not a public runtime dependency.
2. Retain attribution to Relay guidance for bounded context and authority without
   exporting a producer-internal repository link.
3. Replace the integration/update paragraph with versioned-package semantics:
   direct-copy adoption may select the latest policy between tasks; this flow
   uses its deliberately adopted installed version throughout a task. Consumer
   resolution, fixed parent profile and no moving runtime routing stay.
4. Replace the source-relative adoption-guide paragraph with a working
   package-local link. Setup remains optional execution context.

The runtime note changes only its local adoption-guide link. The package-specific
adoption guide preserves integration choices, permissions, role precedence,
configuration caveats and fresh-session verification without private links or
host-specific source paths. Producer-only tests compare the full policy and
runtime projections with independently accepted source after these enumerated
substitutions. Other policy changes must first be proposed in canonical source
and deliberately mapped into a separately reviewed package update. There is no
generator, synchronization service or second VibeVM resolver.

The child matrix guides delegation assignments. General model/effort evidence
and recommendations are a separate producer responsibility. Later updates must
reconcile changed recommendations semantically; neither package overrides the
other or chooses a consumer's admitted profiles. No cross-package dependency is
introduced.

## Local qualification

From the package root, with Python 3.11+:

```sh
python -B tests/check_package.py
```

This portable offline check covers the manifest/boot contract, payload passivity,
policy/profile invariants, public-reference boundaries, MIT notice and local
Markdown targets. It needs no source checkout, Git history or network. Complete
source equivalence and producer change-scope checks run in the producer's tests,
not in the public payload.

The [native disposable-consumer test](tests/qualify_local.py) uses an existing
Linux x86_64 VibeVM **1.0.7** binary with SHA-256
`20d111df02eb28040ef4cb766bfcb0bde8ff4427b031f88f33eacb3711c3e240`:

```sh
python3 tests/qualify_local.py --vibe /absolute/path/to/vibe
```

All native installation and generated files belong to a temporary fixture with
isolated VibeVM settings. These tests do not install this package into the
producer or any real consumer. See [qualification evidence](QUALIFICATION.md)
for recorded results and limits. Document/materialization checks do not prove
model-visible instruction loading, client configuration, useful delegation,
actual child profiles or downstream adoption. Native Windows/macOS and remote
transport remain unqualified.
