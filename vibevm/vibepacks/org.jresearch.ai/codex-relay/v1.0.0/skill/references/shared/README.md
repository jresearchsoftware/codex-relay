# Development Governance

`org.jresearch.ai/development-governance` is one passive VibeVM flow,
licensed under MIT. One whole-package version covers its conditional boot and
ordinary [proportional-controls](vibevm/vibespecs/protocols/proportional-controls.md),
[requirement-authority](vibevm/vibespecs/protocols/requirement-authority.md),
[package-versioning](vibevm/vibespecs/protocols/package-versioning.md)
and [task-handoff](vibevm/vibespecs/protocols/task-handoff.md) protocols,
plus conditional [producer self-adoption](vibevm/vibespecs/protocols/self-adoption.md).
It also offers [workflow-aware GitHub repository governance](vibevm/vibespecs/protocols/github-repository-governance.md)
for explicit topic adoption: conditional PR, direct-main, publication and mixed
paths, proportionate protections, a short setup checklist and event-based
verification. Guidance does not apply GitHub settings or authorize mutation.
It has no executable capabilities, dependencies or native Codex Skills.

The stable contract preserves the proportional-controls procedure, exceptions
and applicability. Its existing-proof and self-imposed-friction guidance reuse
current evidence and project authority without additional operator steps.
Requirement-authority is a common interpretive rule, conditionally read for
relevant provenance decisions; it does not supply a contract-review procedure.
Package-versioning is available for explicit project adoption;
installation or a dependency update does not supersede existing local policies.
Task-handoff likewise requires explicit project adoption. It connects current
Task authority, work identity, short handoffs, exact results, substantive independent assessment
and authorized continuation. One Step is an authorized execution cycle ending
in a terminal result; subsequent new execution advances Step even on the same PR.
The charter stays historical from first execution, with chronological authorized
Decisions. Minimal handoffs navigate to that authority. Direct acceptance permits
immediate qualified approval; Deliberative acceptance requires non-approving review
and owner discussion/Decision before formal approval. Project bindings retain
authorization, review sufficiency and identity requirements without redefining
shared Step semantics. One canonical Outcome follows the whole actual Step result:
exclusively one result PR uses that PR; no PR, known multiple result PRs or a PR
plus an independent Task-level result uses the Task. Unresolved binding stops
publication; replay does not duplicate the Outcome. Manual/single-account limits
remain explicit.

The 2.0.0 task-handoff contract changed earlier project-defined
Step interpretations, Outcome publication routing and immediate approval of
decision-grade results may need migration. This is a MAJOR change, not an additive
topic or silent consumer update. Version 2.1.0 adds repository-governance as an
explicitly adopted topic; the five existing protocols remain unchanged.
Existing consumers retain their accepted local rules until separately reviewed
adoption; frozen versions are retained.
Human-owned project instructions retain task, review, publication and adoption
authority. Newly adopting producers choose their own cadence and routing.
Self-adoption is a compatible addition available for explicit adoption only where
a producer consumes its own guidance. It separates accepted source from public
publication and candidate rules from authority, preferring supported native
ready-file workflows without imposing this producer's implementation on consumers.

Canonical source is [shared-governance](https://github.com/jresearchsoftware/shared-governance).
Version tags and publication history are in the
[distribution repository](https://github.com/jrs-vibevm/org.jresearch.ai.development-governance/tags).
`DISTRIBUTION.json` binds an export to its exact source commit. Frozen releases
are retained; corrections use later versions. The frozen `0.1.0` release is a
historical artifact with its original wording and content.
