# Shared governance and Relay product bindings

This repository deliberately adopts Shared Governance **7.0.1** as the single
canonical source of its portable development governance. The immutable
producer is
`1110f10b996c2f81fa842e6339ab6d7c13111cd7`; the distribution is
`f9fcfa03dec8fb9e00398fc7e0cc7de92da687b9`. Root [AGENTS](../AGENTS.md)
explicitly adopts all nine complete applicable protocols. Their conditional boot
pointer selects reading, never individual clauses. The authored
[product Skill](../packages/codex-relay/skill/SKILL.md) preserves the product
bindings below. Native delivery reads complete shared protocols from the
consuming project's reviewed lock and selected Shared slot through its generated
`references/shared-protocols.md`; standalone includes the attributed immutable
5.0.0 snapshot. Consumers deliberately select and adopt their own compatible
Shared dependency. No fixed bundled native route supersedes that selection.
The historical
[Task #108 analysis](task-handoff-methodology-analysis.md) and earlier
[2.1.0 assessment](vibevm-semantic-coverage.md) remain evidence, not active policy.
The bounded [migration assessment](relay-skill-compatibility.md#project-migration-from-500-through-700) records semantic dispositions; it is not a second rule owner.

## Native authority and compatibility

Task Handoff owns portable charter chronology, execution-cycle Step, minimal
handoff, bounded correction, preservation, results and continuation. Relay's
[authority contract](../contracts/README.md#github-native-task-authority) owns
Issue #N, trusted v4 Decisions, immutable admission, protected reservations and
native identities/body digests. Writer alone allocates Step at consumed owner
launch. The Issue's valid Step position is numbering input reconciled with
successful admitted history; labels/titles project the durable result and grant
no execution authority. TH-002/006's ordinary dispatch needs no
extra Decision merely certifying that same start; the native authenticated
command and immutable admission still implement the product trust boundary.
Issue openness alone starts nothing. Current Node admits only v4; exact older
operations preserve selected authority, Step and recovery/publication bindings
through frozen original source. Historical Requests supply no current execution
fields or extra migration gate. A selected trusted v3 Decision remains bounded
provenance for an admitted v4 result; fresh admission requires every effective old
field to be replaced by later active v4 authority. Fully shadowed existing evidence
needs no new Decision or formal supersession. Shared adoption neither renumbers
history nor qualifies an installation.

The canonical [manual](../packages/codex-relay/skill/references/workflow.md)
retains automatic, admitted-manual and explicitly authorized standalone routes.
Manual operation does not fabricate admission or Writer provenance. The full
copyable admitted prompt and profile remain available; its snapshot is subordinate
to live canonical authority. Exact thread-title/readback is a client binding.

## Result and acceptance bindings

Task Handoff owns Direct/Deliberative verdict timing. The evaluator resolves the
current strategy from effective Task authority and TH-022–025 before native
publication. Deliberative uses a substantive non-approving assessment and owner
Decision before a formal verdict, never fake REQUEST_CHANGES or a post-APPROVE
hold. This human/tool binding does not claim a new runtime strategy classifier.

Relay's [Reviewer contract](../reviewer/README.md#independent-review-and-finding-provenance)
retains a qualified independent native actor, exact complete SHA, required
checks, typed CR, no-PR Task Approval and protected owner continuation. Shared
Independent Review owns assessment/evidence/finding/rereview methodology,
including blocker obligation/source and separation of defects, evidence gaps,
baseline debt and proposed requirements. One owner-account assessment cannot
satisfy Relay's stronger native identity requirement.

The supported Writer source-result route binds one durably identified PR and
one canonical Outcome. Ambiguous PR creation cannot fall back to the Issue.
Shared TH-014–017 covers actual complete/mixed results without requiring new
multi-PR orchestration; extending Relay's unique-artifact runtime capability
requires separate product authority and qualification. No-PR analytical or
qualification results use the Issue without an artificial PR or commit.
Draft/Ready transitions remain Writer-owned and exact-head-bound (TH-028).

## Temporary legacy closure binding

Repository development governance selects Shared 7.0.1. The supported product
closure contract retains its previously qualified legacy flow. Task
[#194](https://github.com/jresearchsoftware/codex-relay/issues/194) alone implements,
qualifies and publishes the new product semantics; source adoption does not
activate them or authorize installation. Follow the existing
[closure authoring](../contracts/README.md#closure-policy-authoring) and
[trusted continuation](../contracts/README.md#authorized-continuation-after-independent-acceptance) contracts:
non-closing PR references, explicit `closesTask: false`, neutral squash messages,
effective completion evidence and separately authorized owner post-merge closure under the
effective `close-authorized` policy. No new closing-link instruction or fictitious
closure approval is added. Historical/admitted authority and explicit holds stay
intact. Missing or conflicting metadata prevents unsafe closure; its legacy
fail-safe is not proof of an owner-selected indefinite hold.

This is the already authorized Relay-only transition described in #194, limited
to actually qualified legacy combinations and behavior. It remains permitted
pending the first Relay release implementing and qualifying the new closure
semantics, then for 60 calendar days from that release's **verified publication**.
Shared 7.0.1 publication starts no clock. Record the actual release/source,
publication event and derived deadline in the existing Issue/release chronology
when verified; no trigger date is asserted here. Removal requires a separately
accepted future Shared release no earlier than the window's end; expiry does not
automatically remove the fallback. This exception extends to no other protocol,
consumer or unknown version. The product floor is not blanket compatibility proof.

Shared TH-026/RA-006 owns the target single-field meaning, including completing
versus intermediate results, condition verification and no-PR work. Runtime
implementation/qualification of those changes remains #194. Protected
host/deployment/recovery permissions remain in the [deployment contract](../deploy/README.md).

## Package, producer and repository bindings

Shared Package Versioning owns lifecycle classification, first accepted frozen
identity and actual dependency closure. Guidance uses the stable authoring root
`packages/codex-relay/skill` and selected identities in `guidance/source.json`.
Version **3.0.0** removes native bundled Shared protocol paths and changes
dependency routing/packaging; its major is independent of Shared major numbers.
Accepted earlier registry payloads, including 2.0.1, remain immutable. The native
VibeVM resolver/projector,
exact schema/workflow pins, generator, source release and external publication
mechanics remain [Relay delivery](relay-guidance.md) responsibilities.
The accepted Shared Publisher and successful-main flow retain their existing
authority. The external caller follows publisher `@main`, while each execution
binds its own exact implementation through `job.workflow_repository` and
`job.workflow_sha` and keeps the producer at the resolved exact accepted SHA:
the triggering push-CI head, manual dispatch event commit when input is blank,
or explicitly supplied recovery SHA.
The publisher reports both immutable identities; callers do not select a
separate publisher revision. Current tree-v1 closure qualification can use
source-time lock/slots beneath the package root without exporting them.
Existing frozen Relay payloads retain their deliberately exported evidence;
a future thin-package change needs separate authorization and a new version.
See [Relay delivery](relay-guidance.md#shared-publisher-and-immutable-publication)
for retry identity, native/offline limits and immutable-tag safeguards.
This integration changes no Shared protocol adoption or release authority and
introduces no additional release gate. A consumer-only
compatible or irrelevant Shared update needs no Relay release. Assess actually
used protocol semantics, applicability, exceptions and product bindings; a change to Relay's own supported behavior, guidance, interfaces, requirements,
packaging or shipped immutable bytes needs its own classified release (PV-018).
The root 7.0.1 lock is outside that product; frozen standalone and included
release-evidence snapshots stay 5.0.0 and remain checked under PV-013. They never
replace the native consumer's selected protocol authority (PV-015). See the
[compatibility assessment](relay-skill-compatibility.md).

Shared Producer Self-Adoption owns accepted-source/candidate separation and
committed ready state. The [native runbook](self-adoption.md) retains exact
registry/slot/projection commands, byte checks, rollback and the known client
sandbox boundary. Structural/tool probes establish files and native discovery,
not model compliance or production installation.

Shared GitHub Governance owns workflow/protection choices, one-time adoption
inspection and event-driven rechecks. Relay source uses PRs, exact-head public
CI and independent native review; human contributions remain available through
[CONTRIBUTING](../CONTRIBUTING.md). Relay's GitHub App identities, rulesets,
workflow projections, deployment/configuration and protected settings mutations
remain local. Settings inspection changes no permissions. Consumer policy,
models, credentials, checks, runners, language, local Skills and overlays remain
owner-controlled; installing guidance does not rewrite them.
