### 1. Repair first-install ACME ordering — demonstrated defect, narrowest correctness fix

**Scope:** [fresh_completion and scheduling](../../deploy/intent_install.py#L296), [host TLS preflight](../../deploy/host_preflight.py#L668), `deploy/tests/test_intent_install.py` and existing preflight tests. Move the existing ACME dry-run/issuance after inactive bootstrap, credentials and CA preparation, before readiness Apply. The baseline schedules it after Apply, whose existing-install gate correctly requires the certificate. Step 3's unassisted flow failed `HOST_TLS_ISSUANCE_STAGE_REQUIRED`; assisted public issuance restored it. This violates the existing product-managed first-install promise. Introduction commit is undetermined; the defect predates this report.

**Acceptance:** execute the coupled composition/preflight path, not a mocked ordering assertion alone. Unassisted fresh installation reaches ready; missing/partial existing-install certificates still refuse; failed dry-run/issuance never activates; credential/CA/Apply/pool failures preserve same-pair pending state and original-operation recovery; changed pair and lost lock refuse. Keep final TLS/ingress/readiness proof. This is a correctness/recovery reduction, with no quantified speedup target or new owner certificate prerequisite.

### 2. Deduplicate shared reconciliation — low-risk, measured and independently shippable

**Scope:** `deploy/ansible/site.yml`, `tasks/execution-slot.yml`, `roles/relay_codex_runtime/tasks/repository-work-root.yml`, shared portions of `roles/relay_runner/tasks/main.yml` and their existing qualification tests. Install Bubblewrap once before all slot probes; hoist unique shared groups/common parents and repeated identical repository ancestors within each slot. Preserve direct-role/legacy, disabled management and retained Reviewer-publication continuation behavior. Keep every route, slot-private credential/diagnostic destination, fixed wrapper/sudoers byte set, namespace probe and retained descendant. Sudoers destinations differ by slot: do not remove their distinct reconciliation as if all 32 writes were duplicates.

**Observed cost:** the completed 442.946347 s bootstrap site measured 31 duplicate Bubblewrap APT calls / **19.870010 s (4.49%)**. This is the gross observed repeated-work cost, not achieved savings and not the principal explanation for a roughly ten-minute PROD APPLY interval. Ancestor inspection/reconciliation 25.815091/27.080230 s and shared/private parent work 25.052661 s include necessary work; their totals must not be promised or summed as removable savings.

**Acceptance:** one package installation per eligible traversal, exactly 31 duplicate calls removed, all 32 route identities/probes retained. Compare capacity 1/2/32, missing package, APT failure, management off and retained continuation. Verify UID/GID/modes/content and no modifications under retained descendants. Preserve current directory-alias refusal and fixed-path metadata repair, together with the existing no-follow, regular-file, link-count, ownership/mode/size checks at credential and protected acquisition boundaries. Compare same-pair/capacity/cache/toolchain baseline/candidate totals and package counts. No absolute seconds SLA is justified by this single sample.

### 4. Skip unchanged-component restarts with equivalent adoption proof — targets code-only updates

**Scope:** `deploy/ansible/tasks/upgrade-lifecycle-activate.yml`, `upgrade-lifecycle-validation.yml`, Reviewer artifact/runtime config rendering and existing process validation/tests. Derive a transient restart-needed decision from verified binary plus effective runtime config, unit/environment, bind, credentials/CA/policy and startup-sensitive dependencies. `reviewer-mcp.json.j2` includes per-product provenance; Rust validates then drops those metadata fields when constructing runtime configuration. A new overall product SHA or metadata-only config difference need not imply changed Reviewer behavior, but all effective inputs must be compared.

**Acceptance:** for unchanged effective inputs preserve PID/start and verify actual `/proc` executable digest, **loaded** effective configuration and service/pool health; for changed inputs require the current changed-start/adoption proof. Disk-file comparison alone cannot prove cached in-memory policy, CA or environment. The current `upgrade-reviewer-config-adoption.yml` explicitly uses guarded restart for that proof. A new path therefore needs bounded loaded-input evidence through an explicitly scoped private/authenticated interface, with no secrets exposed; missing proof retains restart. Reviewer currently exposes `/mcp`, not a loaded-config health endpoint. Any new read-only proof capability belongs to the explicitly authorized implementation and must preserve mTLS, private listener and RPC origin boundaries; no unauthenticated health bypass. Include changed binary, App/repositories/policy/bind/environment/unit/key/CA, unexpected process, corrupted stage, stopped service, lost lock and interrupted cutover. Retain Production Runner dependency behavior, originally-active/inactive states and frozen old-attempt recovery. Prove no stale loaded process can be accepted. No measured restart savings or exact historical restart command is available. This changes process-adoption semantics and needs explicit owner disposition and same-change contract documentation before implementation.
